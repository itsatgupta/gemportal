## 📌 Project Overview

**Client:** ANAMAC  
**Application:** Bid Proposal Intelligence Platform  
**Purpose:** Automate the end-to-end government bid lifecycle — from discovery on the GEM portal to proposal drafting, assessment, gap resolution, and final approval — using a coordinated team of AI agents.  
**GEM Portal URL:** https://bidplus.gem.gov.in/all-bids  
**Deployment:** Local web server (initial), production-ready build

## 🤖 Agent Definitions

### Agent 1 — `search_agent`
**Role:** Bid Discovery & Document Acquisition  
**Trigger:** User enters bid type (QRA, HAZOP, etc.) in the Search tab and clicks "Search Bids"

**Responsibilities:**
1. Navigate to `https://bidplus.gem.gov.in/all-bids`
2. Search for bids matching the user's query (bid type, keywords)
3. List matching bids with metadata (bid number, title, deadline, department)
4. Download the primary bid PDF document
5. Parse all hyperlinks inside the bid PDF
6. Download every linked supporting document
7. Create folder: `bids/{BID_NUMBER}/`
8. Store primary bid PDF as `bids/{BID_NUMBER}/bid_document.pdf`
9. Store all linked docs in `bids/{BID_NUMBER}/supporting_docs/`
10. Broadcast status updates via WebSocket to frontend
11. Notify `bid_proposer_agent` when download is complete

**Tools Used:**
- `gem_scraper.py` — Playwright/Selenium-based GEM portal navigation
- `pdf_downloader.py` — PDF fetching + hyperlink extraction
- `file_manager.py` — Directory creation & file storage

**Status States:** `idle` → `searching` → `downloading` → `extracting_links` → `complete` → `error`

---

### Agent 2 — `bid_proposer_agent`
**Role:** Bid Proposal Generation  
**Trigger:** User clicks "Prepare Proposal" tab after bid documents are downloaded

**Responsibilities:**
1. Read all documents in `bids/{BID_NUMBER}/` and `bids/{BID_NUMBER}/supporting_docs/`
2. Read all supporting company docs from `bidsupportingdocs/`
3. Analyze bid requirements (scope, eligibility, technical requirements, deadlines)
4. Generate a comprehensive bid proposal aligned with GEM standards
5. Store proposal as `bids/{BID_NUMBER}/bid_proposal.pdf`
6. Notify `bid_assessor_agent` that proposal is ready for review
7. **Listen for gap reports** from Agent 3 and revise proposal accordingly
8. Re-save updated proposal and notify Agent 3 for re-review

**Tools Used:**
- `document_parser.py` — Extract and analyze bid requirements
- `file_manager.py` — Read supporting docs, write proposal
- DeepSeek API (OpenAI-compatible) — Proposal generation LLM calls

**Status States:** `idle` → `reading_docs` → `drafting` → `proposal_ready` → `receiving_gaps` → `revising` → `revised_ready`

---

### Agent 3 — `bid_assessor_agent`
**Role:** Proposal Quality Assessment & Gap Analysis  
**Trigger:** Automatically triggered when Agent 2 marks proposal as ready

**Responsibilities:**
1. Read `bids/{BID_NUMBER}/bid_proposal.pdf`
2. Compare against original bid document requirements
3. Identify gaps, shortcomings, compliance issues, missing documents
4. Generate structured gap report with severity levels (Critical / Major / Minor)
5. Send gap report to Agent 2 for resolution
6. **Re-review** the revised proposal once Agent 2 has updated it
7. If no major issues remain:
   - Write final summary with observations from initial review and re-review
   - Store as `bids/{BID_NUMBER}/assessor_summary.txt`
8. If major issues still exist → loop back to Agent 2

**Gap Report Format:**
```json
{
  "gap_id": "GAP-001",
  "severity": "Critical|Major|Minor",
  "section": "Technical Specifications",
  "description": "Missing ISO certification reference",
  "recommendation": "Add ISO 9001:2015 certificate from bidsupportingdocs/certifications/",
  "status": "open|resolved"
}
```

**Summary Report Format (assessor_summary.txt):**
```
ANAMAC BID ASSESSMENT SUMMARY
Bid Number: {BID_NUMBER}
Assessment Date: {DATE}
Assessor Agent: bid_assessor_agent v1.0

INITIAL REVIEW OBSERVATIONS:
- [Gap 1 identified...]
- [Gap 2 identified...]

RESOLUTION REVIEW:
- Gap 1: Resolved ✓
- Gap 2: Resolved ✓

FINAL VERDICT: APPROVED / CONDITIONALLY APPROVED
SUMMARY COMMENTS: [Narrative of overall proposal quality]
```

**Status States:** `idle` → `reviewing` → `gaps_found` → `sent_to_agent2` → `re_reviewing` → `approved` → `conditionally_approved`

---

### Agent 4 — `qa_agent`
**Role:** Application Quality Assurance & Testing  
**Trigger:** Developer command `python backend/qa/qa_agent.py --run-suite`

**Responsibilities:**
1. Test GEM portal connectivity and scraping accuracy
2. Validate document download integrity (file sizes, PDF validity)
3. Test agent-to-agent communication flows
4. Validate folder structure creation per bid
5. Test proposal generation quality metrics
6. Test gap report schema validation
7. Test WebSocket real-time updates
8. Test frontend tab flows and state transitions
9. Generate HTML test report in `qa_reports/{timestamp}/`
10. Flag production-blocking issues

## 🚀 Local Deployment — Step by Step

### Prerequisites
```bash
# Install required software
node --version        # >= 18.0.0
python --version      # >= 3.11.0
pip --version
```

### Step 1 — Clone & Setup
```bash
git clone <repo-url> anamac-bid-platform
cd anamac-bid-platform
cp .env.example .env
# Edit .env and add your DEEPSEEK_API_KEY
```

### Step 2 — Backend Setup
```bash
cd backend
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium        # For GEM portal scraping
```

### Step 3 — Frontend Setup
```bash
cd ../frontend
npm install
```

### Step 4 — Create Required Folders
```bash
mkdir -p bids
mkdir -p bidsupportingdocs
# Add your company documents to bidsupportingdocs/
```

### Step 5 — Run the Application
```bash
# Terminal 1 — Backend
cd backend
source venv/bin/activate
uvicorn main:app --reload --port 8000

# Terminal 2 — Frontend
cd frontend
npm run dev
```

### Step 6 — Access
Open browser: `http://localhost:5173`

### Step 7 — Run QA Suite
```bash
cd backend
python qa/qa_agent.py --run-suite
# View report: qa_reports/{timestamp}/report.html
```

## 🔄 Agent Workflow — Complete Lifecycle

```
USER INPUT (bid type)
      │
      ▼
┌─────────────────┐
│  search_agent   │ ──── Searches GEM portal
│  (Agent 1)      │ ──── Downloads bid PDF
│                 │ ──── Extracts & downloads hyperlinks
│                 │ ──── Creates bids/{BID_NUMBER}/
└────────┬────────┘
         │ notify: "bid_downloaded"
         ▼
┌─────────────────────┐
│ bid_proposer_agent  │ ──── Reads bid requirements
│ (Agent 2)           │ ──── Reads bidsupportingdocs/
│                     │ ──── Generates bid_proposal.pdf
│                     │ ──── Stores in bids/{BID_NUMBER}/
└──────────┬──────────┘
           │ notify: "proposal_ready"
           ▼
┌─────────────────────┐
│ bid_assessor_agent  │ ──── Reviews proposal vs bid
│ (Agent 3)           │ ──── Identifies gaps
│                     │ ──── Sends gap report to Agent 2
└──────────┬──────────┘
           │ gap_report sent to Agent 2
           ▼
┌─────────────────────┐
│ bid_proposer_agent  │ ──── Receives gaps
│ (Agent 2) REVISION  │ ──── Revises proposal
│                     │ ──── Saves updated proposal
└──────────┬──────────┘
           │ notify: "proposal_revised"
           ▼
┌─────────────────────┐
│ bid_assessor_agent  │ ──── Re-reviews revised proposal
│ (Agent 3) RE-REVIEW │ ──── Checks all gaps resolved
│                     │ ──── Writes assessor_summary.txt
│                     │ ──── APPROVED ✓
└─────────────────────┘
           │
           ▼
     FINAL SUMMARY TAB
     (UI shows approval seal + full summary)
```

## 📋 Agent Communication Protocol

All agents communicate via a shared message bus (FastAPI WebSocket broadcast):

```python
# Message schema
{
  "from_agent": "search_agent | bid_proposer_agent | bid_assessor_agent | qa_agent",
  "to_agent": "bid_proposer_agent | bid_assessor_agent | all",
  "message_type": "status_update | gap_report | revision_complete | approval | error",
  "bid_number": "GEM-BID-XXXXX",
  "payload": { ... },
  "timestamp": "ISO 8601"
}
```

### Key Bugs Fixed During Build
1. **Python 3.9 compat** — Added `from __future__ import annotations` to all files; used `Optional[]` for FastAPI route params (Pydantic evaluates at runtime)
2. **PDF download failing** — The GEM portal `showbidDocument/{id}` URL serves PDF directly (Content-Type: application/pdf), not an HTML page. Removed unnecessary Playwright step; download directly from detail_url
3. **Relative path resolution** — `./bids` in .env resolved to `backend/bids/` when uvicorn runs from backend dir. Fixed config.py `_resolve_dir()` to always resolve relative to ROOT_DIR
4. **Title extraction** — First line of bid card was "View Corrigendum/Representation". Fixed to extract item description from Items field instead
5. **Missing `/` in detail URL** — Some bid links missing leading `/` before `showbidDocument`. Fixed URL construction logic
6. **Read-only routes creating dirs** — `get_bid_document` and `download_full_package` routes were calling `get_bid_dir()` which creates directories as a side effect. Fixed to check path existence directly via `BIDS_BASE_DIR` without creating dirs
7. **Infinite agent revision loop** — Agent 3 kept finding gaps and sending back to Agent 2 indefinitely (40+ messages in one run). Added `MAX_REVISIONS = 2` and `_revision_counts` tracker to `bid_assessor_agent.py`. After max rounds, forces "CONDITIONALLY APPROVED" verdict
8. **assessments.py `get_summary` creating dirs** — Same `get_bid_dir()` side effect as bids routes. Fixed to use `BIDS_BASE_DIR` directly
